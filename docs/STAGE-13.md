# Этап 13: fragment parsing (`Element.innerHTML`)

Этап 12 закончился на 1 153/1 380 (83.6 %), но вне конверта оставались 412 случаев
html5lib — и 155 из них были не «сложные места», а системная дырка: **фрагментный
разбор**. `#document-fragment` в корпусе помечает вход, который парсится не как
документ, а как *дети* заданного элемента: ровно то, что делает `innerHTML = …`.

Здесь эта дырка закрыта целиком: реализован сам алгоритм, корпус начал эти случаи
считать, `innerHTML` в JS перестал быть обёрткой над `<body>`.

## Что сделано

### 1. Контекстный элемент не лежит в стеке

Первая попытка — положить контекст в стек вторым элементом — развалилась сразу:
`</div>` внутри `div`-фрагмента снимал сам контекст, а `</table>` из ячейки
закрывал «таблицу», которой в стеке нет. Пришлось сделать как в стандарте:

```cpp
[[nodiscard]] dom::NodeId current() const {
  // Фрагмент: стек сведён к поддельному <html>, поэтому новые дети идут в контекст,
  // которого сознательно нет в стеке открытых элементов.
  if (fragment_mode_ && stack_.size() <= 1) return context_;
  ...
}
```

Стек содержит только поддельный `<html>`; контекстный элемент создаётся рядом с
ним в документе и отдаётся вызывающему (`parse_fragment` возвращает его `NodeId`).
Следствия, которые и нужны:

* ни одно правило не может «закрыть» контекст — его просто нет в стеке;
* `</div>`, `</tr>`, `</caption>` без пары игнорируются естественным образом;
* foster parenting и `<template>` работают как раньше, потому что всё, что
  смотрит на «текущий узел», смотрит на `current()`.

### 2. «Reset the insertion mode», fragment case

Режим у нас выводится из стека, поэтому для фрагмента он берётся из тега
контекста — с той же оговоркой, что в стандарте (`last` = true, значит правила,
требующие `last == false`, пропускаются):

```cpp
[[nodiscard]] static Mode initial_mode_for(std::string_view tag) {
  if (tag == "tr") return Mode::Row;
  if (tag == "tbody" || tag == "thead" || tag == "tfoot") return Mode::TableBody;
  if (tag == "colgroup") return Mode::ColumnGroup;
  if (tag == "table") return Mode::Table;
  return Mode::Body;  // td/th/caption/select/head/body/… и всё остальное
}
```

Именно из-за этой оговорки `td`-фрагмент разбирается «in body»: `<tr>`/`<td>` в
нём — ошибки разбора, и `cell.innerHTML = "<tr><td>x"` даёт текст `"x"`, а не
вложенную строку. `tr`-фрагмент, наоборот, растит ячейки без таблицы вокруг.

### 3. Токенайзер: состояние контекста без «appropriate end tag»

Для `title`/`textarea` (RCDATA), `style`/`xmp`/`iframe`/`noembed`/`noframes`/
`script` (RAWTEXT) и `plaintext` токенайзер стартует в нужном состоянии. Но
контекстный тег никогда не был выданным стартовым тегом, поэтому «подходящего
закрывающего» у фрагмента нет — новый метод:

```cpp
void Tokenizer::enter_context_text_state(bool rcdata);  // состояние есть, имени нет
```

Из-за этого `script.innerHTML = "a()</script>b"` даёт текст `a()</script>b`, а не
обрезает его на `</script>` — как и ожидает html5lib.

### 4. Скелетные теги документа игнорируются

`<html>`, `<head>`, `<body>`, `<frameset>` во фрагменте — ошибки разбора: стек
содержит только поддельный `<html>`, перестраивать нечего. Раньше `<body>` внутри
`div`-фрагмента вызывал `ensure_body()` и создавал `<head>`/`<body>` в документе,
из-за чего текст перед `<div>` терялся.

### 5. Табличные режимы: «нечего закрывать» ≠ «переразобрать токен»

`pop_through()` теперь возвращает, снял ли он что-нибудь, и никогда не снимает
корневой `<html>`. Это важно потому, что многие правила табличных режимов звучат
как «снять стек до … и переразобрать токен»: если снимать нечего (фрагмент),
переразбор зацикливается. Правила, где стандарт требует «вне scope — игнорировать»
(`<table>` в `<table>`, `</table>` в строке, `<col>` в `colgroup`), получили
явные проверки scope, а «in cell» для табличных тегов свёлся к одному пути:
закрыть ячейку и переразобрать токен на уровень выше. Побочно это починило
`<table><td><td>` в обычных документах: раньше второй `<td>` обрабатывался
правилами «in body» и просто игнорировался.

### 6. «After body»

Мелочь, но она попала в корпус: после `</body>`/`</html>` комментарии остаются
на элементе `<html>` (режим «after body»), а не уходят в `<body>`. Заодно
`</html>` до всякого контента создаёт `<head>`/`<body>` сразу — иначе порядок
узлов не совпадал.

### 7. `innerHTML` в JS: настоящий фрагментный разбор

`set_inner_html` больше не оборачивает вход в `<body>…</body>` и не копирует
дети `<body>`:

```cpp
const std::string tag(document.tag_name(node));
Document scratch(document.source_url());
const dom::NodeId context = html::parse_fragment(html, tag, scratch, nullptr, {});
// дальше — глубокое копирование детей контекста в целевой узел
```

Теперь `td.innerHTML`, `tr.innerHTML`, `table.innerHTML`, `textarea.innerHTML`,
`template.innerHTML` ведут себя как в браузере, а не «как `<body>`». Это видно в
демо [`docs/demo/fragment.html`](demo/fragment.html) (скриншот
[`demo/fragment.png`](demo/fragment.png)).

## Что работает

* `parse_fragment("<p>a<b>b</p>c", "div")` → `<p>a<b>b</b></p><b>c</b>`;
* `("</div><b>x</b>", "div")` → `<b>x</b>` (контекст не закрывается);
* `("<body><head><html><span>x", "body")` → `<span>x</span>`;
* `("<tr><td>x", "table")` → `<tbody><tr><td>x</td></tr></tbody>`;
* `("<td>a<td>b", "tr")` → две ячейки; `("<tr><td>a", "td")` → текст `a`;
* `("foo<col>", "colgroup")` → `<col>` (текст в colgroup отбрасывается);
* `("a&amp;b<b>c", "title")` → текст `a&amp;b&lt;b&gt;c` (RCDATA);
* `("a()</script>b", "script")` → текст целиком (нет appropriate end tag);
* `("<b>no</b>", "plaintext")` → текст целиком;
* `("<input><option>a", "select")` → `<option>a</option>`;
* `("<body>X", "html")` → `<html><head></head><body>X</body></html>`;
* `<p>a</p></html><!--x-->` → комментарий рядом с `<head>`/`<body>`;
* строгая сборка `-Werror` чистая, ASan/UBSan 369/369 без отчётов (и tree-корпус
  под санитайзерами тоже).

## Решение

[ADR 0015](adr/0015-fragment-parsing.md): контекстный элемент фрагмента **не
лежит в стеке открытых элементов**, режим берётся из его тега по «reset the
insertion mode», а «appropriate end tag» у текстовых контекстов отсутствует — три
следствия одного и того же решения «делать как в стандарте, а не как удобно
стеку».

# ADR 0027: прототипы примитивов, обёртки и общий арифметический помощник

Дата: 2026-11-05. Этап: 25.

## Контекст

Методы `String` (а также `toFixed` у чисел) были замыканиями, которые
`get_member` создавал на каждое обращение к конкретному значению. Из этого
следовало: `String.prototype` не существует, `"abc".constructor` — `undefined`,
`String.prototype.trim.call(s)` невозможно, и любой метод, вызванный «не на том»
получателе, ведёт себя непредсказуемо. Плюс не было обёрток `new String('x')` —
то есть `typeof new String('x')` не мог быть `"object"` в принципе.

Отдельная, независимая дыра: разбор составных присваиваний ограничивался пятью
арифметическими операторами.

## Решение

### 1. Примитивные прототипы — тот же приём, что у `Array` (ADR 0026)

`runtime.string_prototype` / `number_prototype` / `boolean_prototype`; методы
живут там, `get_member` при промахе у примитива смотрит в прототип своего типа,
потом в `Object.prototype`. Значение не несёт методов вовсе.

Отвергнуто: создавать для каждого строкового значения объект-обёртку (как делает
спек: `ToObject`). Это аллокация на каждое `s.length` в горячем коде движка;
вместо этого методы принимают примитив как `this`.

### 2. `this` разворачивается помощником, а не приведением

`string_this`/`number_this`/`boolean_this` принимают либо примитив, либо обёртку
и бросают `TypeError` иначе — ровно как спецификация требует для
`String.prototype.*` (`thisStringValue`). Отвергнуто: звать `to_string(this)`
(приведение разрешило бы `String.prototype.trim.call({})` и превратило бы
`TypeError`-тесты в «работает»).

### 3. Обёртки: флаг на объекте, а не отдельный вид

`Object::is_wrapper` + `wrapper_value`. `typeof` смотрит на `ValueType`, поэтому
обёртка — `"object"`; `to_number`/`to_string` разворачивают её; `Object.prototype.toString`
ставит тег по запакованному примитиву.

Отвергнуто: `Object::Kind::String/Number/Boolean` — три новых вида, каждый из
которых пришлось бы обрабатывать во всех местах, где сейчас проверяется
`Kind::Array`/`Kind::Error`. Флаг дешевле и не меняет существующие ветвления.

Как обёртка появляется: конструктор видит, что вызван через `new` (ему передали
объект как `this`), пакует примитив в `this` и возвращает примитив — а `new`
по правилу «нативный конструктор вернул не объект» отдаёт созданный экземпляр.

### 4. Одна арифметика на бинарные выражения и составные присваивания

`apply_arithmetic(op, left, right)` — единственное место, где живут
`+ - * / % ** & | ^ << >> >>>`. `x <<= 1` исполняется как `x = x << 1` по
построению, а не по совпадению двух копий кода (раньше копий было две, и они уже
разошлись: `>>>` не было ни в одной).

`ToInt32`/`ToUint32` реализованы по 7.1.5/7.1.6 (усечение, модуль 2^32, знак),
потому что `static_cast<long long>` на `Infinity`/`NaN` — неопределённое
поведение, а `(-1) >>> 0` должен быть 4294967295.

## Следствия

* test262: 4 571 → **5 130** (31.0 % → 34.8 %); `String` 12.7 % → **24.8 %**,
  `Number` 17.1 % → 26.4 %, `Boolean` 30.4 % → 37.0 %.
* Юнит-тестов 462 → 472; strict-сборка без предупреждений, ASan/UBSan чисто.
* Ограничения: строки по-прежнему UTF-8-байтовые (`"😀".length` = 4), `RegExp`
  нет (замена и `split` работают только со строковым образцом), `localeCompare`
  сравнивает байты, `toExponential` печатает в стиле printf (`1.000000e+00`
  вместо `1e+0`).

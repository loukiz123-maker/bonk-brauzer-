# ADR 0019: DOCTYPE как полноценный токен и quirks-режим по стандарту

**Статус**: принято (этап 17).

## Контекст

Корпус html5lib держит два больших блока, которые мы сознательно обходили:
426 случаев токенайзера и 21 случай дерева связаны с `PUBLIC`/`SYSTEM`
идентификаторами DOCTYPE. Причина была в модели данных: `Token` хранил у
DOCTYPE только имя (`data`), токенайзер «съедал суп из идентификаторов» до `>`,
а парсер ставил quirks-режим по единственному правилу «имя не `html`».

Этого мало по трём причинам:

1. идентификаторы видны в дереве документа (`<!DOCTYPE html "pub" "sys">`), их
   печатает и html5lib, и браузерный `document.doctype`;
2. quirks-режим по стандарту зависит именно от них (55 префиксов public-id,
   два точных public-id, один system-id, отдельный «limited quirks»);
3. без `force_quirks` нельзя отличить `<!DOCTYPE html>` от оборванного
   `<!DOCTYPE html PUBLIC "a"` — а это разные режимы документа.

## Решение

1. **Токен.** В `Token` появились `public_identifier`, `system_identifier`,
   по флагу `has_public_identifier` / `has_system_identifier` (идентификатор
   может быть пустым — `PUBLIC ""` — и это не то же самое, что его отсутствие)
   и `force_quirks`.

2. **Токенайзер.** State machine DOCTYPE реализован целиком (16 состояний):
   `before DOCTYPE name` → `DOCTYPE name` → `after DOCTYPE name` → ветки
   `PUBLIC`/`SYSTEM` → идентификаторы в кавычках → `between … identifiers` →
   `after DOCTYPE system identifier` и `bogus DOCTYPE`. Два правила, которые
   проще всего сделать неправильно:
   * `bogus DOCTYPE` сам **не** включает force-quirks (и не снимает), а EOF в
     нём эмитит токен как есть;
   * EOF в состояниях, ожидающих кавычку, force-quirks включает.
   Отдельный хелпер `emit_doctype(bool)` завершает токен и переводит состояние
   в data/EOF — вместо десятка копий одного и того же кода.

3. **DOM.** `create_doctype(name, public_id, system_id)`; узел хранит два
   интернированных id, `kNoNode` = «идентификатора не было». Сериализаторы
   (`to_html`, раннер tree-корпуса) печатают их тогда и только тогда, когда они
   есть, — иначе `<!DOCTYPE html>` навсегда превратился бы в
   `<!DOCTYPE html "" "">`.

4. **Quirks.** `doctype_mode(token)` → `Standards` / `LimitedQuirks` / `Quirks`,
   со списками стандарта (55 префиксов + два точных значения + IBM system-id).
   `quirks_` в парсере теперь булев результат этого сравнения. `LimitedQuirks`
   отделён от `Quirks` явно: в разборе он ведёт себя как standards, различие
   относится к layout.

## Последствия

* Токенайзер: 6 281 → **6 707/6 820 (98.3 %)**, 0 падений, пропусков 539 → 113.
* Дерево: 1 535 → **1 556/1 556 (100 %)** при 236 случаях вне конверта
  (внешний контент); «skipped doctype-identifier cases» больше не существует.
* `Token` стал тяжелее (три `std::string` + три `bool` на токен): это цена за
  то, что DOCTYPE перестал быть «именем и мусором». Синтетические токены
  строятся через `plain_token()`.
* `to_html()` печатает идентификаторы — это заметное изменение вывода для
  документов с legacy-DOCTYPE (например `<!DOCTYPE html PUBLIC
  "-//W3C//DTD HTML 4.01//EN" "…">`).
* Следующий крупный блок — внешний контент SVG/MathML: он требует не только
  новых состояний, но и пространств имён в DOM, case-adjust и breakout-тегов.

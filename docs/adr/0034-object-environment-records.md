# ADR 0034: окружения имён как объекты — `with` и глобальный объект

Дата: 2026-11-06. Этап: 32.

## Контекст

До этого этапа имя в движке разрешалось одной функцией:

```cpp
Lookup lookup_scope(const ScopePtr& start, const std::string& name);
```

Она шла по цепочке `Scope::variables` — то есть знала ровно один вид
окружения: «словарь имён». Стандарт знает больше: у имени может быть
*объектное* окружение (Object Environment Record), где привязками служат
свойства объекта. Таких окружений в языке два:

1. `with (object) statement` — объект ставится перед текущей областью;
2. глобальное окружение — свойства глобального объекта **и есть** глобальные
   переменные (`this.p1 = 1` создаёт имя `p1`, `var p2` читается как
   `globalThis.p2`).

Второе было сломано незаметно: `globalThis` существовал как пустой объект, а
глобальные переменные жили в `Scope::variables` — две несвязанные таблицы.
Именно поэтому падали `with`-тесты, написанные ещё под ES5, хотя сам `with` к
ним отношения не имел.

## Решение

### 1. Разрешение имени — отдельная сущность, а не `map::find`

Появился `resolve_name(scope, name)`, возвращающий `NameRef` одного из трёх
видов:

```cpp
struct NameRef {
  enum class Kind { Unresolvable, Slot, Property } kind;
  ScopePtr scope;   // Kind::Slot: слот в словаре имён
  Value object;     // Kind::Property: свойство объекта (with-окружение)
};
```

Поверх него — три операции: `read_name`, `write_name`, `has_name`. Через них
проходят **все** места, где движок трогает имя: чтение идентификатора,
`typeof` (которому нужно «есть ли имя вообще»), присваивание и составные
присваивания, `++`/`--`, деструктуризация (`store_target`), `for-in`/`for-of`
с идентификатором-целью, `delete name`.

Это была главная цена решения: `with` работает только там, где разрешение
имени централизовано. Полумера («научить `with` чтению, остальное потом») даёт
оператор, который в `with (o) { o.x = 1 }` ведёт себя правильно, а в
`with (o) { x++ }` — нет.

### 2. `with` — область видимости с объектом

`Scope` получил поле `Value with_object` (`undefined` = «не with-окружение»).
`resolve_name` при обходе цепочки для каждой области сначала смотрит в
`variables`, затем — если это with-окружение — спрашивает `HasProperty`
объекта. `HasProperty` идёт по цепочке прототипов **и** по неявным прототипам
(`Object.prototype`, `Array.prototype`, `Function.prototype` — они живут в
рантайме, а не в каждом объекте), но не запускает геттеры: стандарт требует
именно проверки наличия, а не чтения (`with (o) { x = 1 }` не должен лишний раз
вызывать геттер `x`).

Запись в свойство идёт через `set_member`, поэтому строгие правила
(неперезаписываемое свойство → `TypeError`) работают и внутри `with`.

Примитивы упаковываются на входе: строка даёт собственные `length` и индексы,
остальные — пустой объект (полноценные обёртки `Number`/`Boolean` с их
прототипами не нужны: снаружи они всё равно видны только как имена).

Отвергнуто: «развернуть `with` в переименование имён на этапе разбора». Тело
`with` может содержать `eval`, вложенные функции и `delete`; статически
вычислить, какие имена перехватит объект, нельзя.

### 3. Глобальный объект — это глобальные переменные

`Object::is_global_object` — флаг ровно на одном объекте в контексте.
`get_member`/`set_member` для него читают и пишут `RuntimeState::global`
`variables`; `has_property_chain` (нужный `with`-окружению и оператору `in`)
и `in` тоже смотрят в глобальную область.

Отвергнуто: сделать `globalThis` «прокси»-объектом с колбэками на таблицу имён.
Колбэки пришлось бы добавлять в четыре разных места (`get`, `set`, `has`,
`ownKeys`), а флаг проверяется в тех же четырёх местах одним `if`.

Отвергнуто: перевести глобальные переменные в таблицу свойств объекта. Тогда
`variables` перестал бы быть словарём, а на него опираются замыкания, `eval`,
`lookup_scope` для встроенных объектов и вся обвязка `Context`.

### 4. `this` берётся из функциональной области

`this` в интерпретаторе читался как `scope->this_value`, то есть из ближайшей
области. Но блок (`{ }`), цикл и `with` создают области — значит `this` внутри
любого блока был `undefined`, и `with (myObj) { this.p2 = 'x2' }` падало с
`cannot set property … of undefined`. Исправление — `lookup_this(scope)`,
который уже существовал для вызовов `super`: идти вверх до
`is_function_scope` и брать `this_value` оттуда.

## Последствия

* Positive: `with` (60 файлов в `language/statements/with` осталось, было 154),
  `switch`, метки, глобальный объект и `\uXXXX` в идентификаторах дали +349
  пройденных файлов test262 без изменения конверта.
* Positive: `this` внутри блока/цикла/`with` больше не `undefined` — это была
  ошибка, которая проявлялась и вне `with`.
* Negative: разрешение имени стало чуть дороже (дополнительный `if` на каждую
  область цепочки), а `write_name` возвращает `bool` «разрешилось ли», чтобы
  вызывающий код применял правило sloppy-глобала. Это чуть менее очевидный
  контракт, чем «нашли или исключение».
* Negative: `with` не кэшируется и не оптимизируется; при появлении
  inline-кэшей для имён `with` придётся либо выключать их, либо сбрасывать.
  Записано в открытые пункты.
* Negative: `delete globalThis.x` по-прежнему удаляет «в никуда» (глобальные
  переменные не конфигурируемы, но `false` не возвращается) — мелкая
  неточность, отмечена в открытых пунктах этапа.

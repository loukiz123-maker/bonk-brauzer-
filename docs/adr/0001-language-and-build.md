# ADR 0001 — C++20 + GNU make как канонический стек

**Статус:** принято (этап 0)
**Контекст:** ТЗ допускает Rust (Cargo) или C++20 (CMake).

## Решение

Движок пишется на **C++20** (`-std=c++20`, без расширений), каноническая сборка — **GNU make**
без внешних зависимостей; `CMakeLists.txt` поддерживается в актуальном состоянии для IDE и CI.

## Почему

1. В окружении разработки доступен только `g++ 12`, а `static.rust-lang.org` и `crates.io`
   недоступны — Rust-код нельзя ни собрать, ни протестировать. Непроверяемый код не считается
   рабочим.
2. `make` + один компилятор = сборка на любой машине без сети. `cmake` в том же окружении
   отсутствовал, поэтому основной путь обязан быть самодостаточным.
3. C++20 даёт ровно то, что нужно движку: `std::variant` (Result), `std::span`,
   `std::string_view`, `concepts` для шаблонов тест-фреймворка, `constexpr` для таблиц.

## Последствия

- Без GC и borrow-checker: дисциплина владения зафиксирована в `docs/ARCHITECTURE.md`
  (арена на документ + генерационные `NodeId`), санитайзеры в CI обязательны.
- `Makefile` и `CMakeLists.txt` дублируют список исходников; оба используют glob, поэтому
  новый файл не требует правок ни в одном из них. CI собирает обоими путями.
- Порт на Rust при необходимости — по контрактам из `ARCHITECTURE.md`, без изменения дизайна.

# ADR 0020: пространства имён в DOM и правила «in foreign content»

**Статус**: принято (этап 18).

## Контекст

Корпус дерева html5lib держал 236 случаев «вне конверта» — все, где в дереве
появлялся `<svg>` или `<math>`. Обойти их было нельзя не из-за правил разбора,
а из-за модели данных: `Node` не хранил пространства имён, поэтому `<svg svg>`,
`<math mi>` и HTML-`<div>` были одним и тем же — элементом с именем. Без
пространств имён не работают три вещи, на которых держится вся эта часть
стандарта:

1. **интеграционные точки** — `foreignObject`, `desc`, `title`, `mi`, `mo`,
   `mn`, `ms`, `mtext`, `annotation-xml` попадают в HTML-правила не по имени, а
   по «имя + пространство имён»;
2. **breakout-теги** — `<b>` внутри `<svg>` обязан стать HTML-элементом, а
   `<font>` — только если у него есть `color`/`face`/`size` (у SVG есть свой
   `<font>`);
3. **проверки области видимости** — `<svg td>` не ячейка таблицы, `<svg
   template>` не шаблон; без этого `</td>` и `</template>` «находят» не те
   элементы и ломают дерево.

## Решение

1. **Пространство имён как поле узла.** `dom::Namespace { Html, Svg, Mathml }` в
   `Node::ns`, `create_element(name, ns)`, `element_namespace(id)`. Отдельный
   тип узла не годится: элемент остаётся элементом, у него просто другое
   пространство имён, и все обходы/селекторы/лейаут должны видеть его как
   обычный элемент.

2. **Префикс — часть атрибута.** `Attribute::prefix` (пустой = нет префикса).
   `set_attribute(el, name, value)` пишет и ищет только беспрефиксные
   атрибуты, `set_attribute(el, prefix, name, value)` и
   `attribute_ns(el, prefix, name)` — префиксные. Иначе `xlink:href` и `href`
   стали бы одним атрибутом.

3. **Диспетчер вместо ветвлений по месту.** `use_foreign_rules(token)` — единая
   точка входа для каждого токена (`process_start_tag` / `process_end_tag`).
   HTML-сторона (`handle_start_tag` / `handle_end_tag_name`) вызывается
   напрямую из «reprocess in HTML content», минуя диспетчер: иначе breakout
   возвращается в только что покинутые правила и, например, `</br>` в `<mtext>`
   зацикливается навсегда.

4. **Таблицы из стандарта, а не из головы.** 37 имён SVG-элементов, 58 имён
   SVG-атрибутов, одно MathML-имя (`definitionurl`) и 11 префиксных атрибутов
   выгружены из текста стандарта (`source` whatwg/html) скриптом и лежат
   таблицами в `tree_builder.cpp`. `solidcolor` в таблицу не попал: в стандарте
   он закомментирован, и корпус ждёт имя без изменения.

5. **Namespace-aware обходы стека.** Все проверки «есть ли `<p>` в области
   видимости», «что за текущий режим вставки», «где ближайший `<template>`»
   сравнивают (имя, пространство имён) через `is_html_named`. Интеграционные
   точки при этом — границы области видимости (`is_scope_boundary`).

6. **CDATA — через флаг, а не через знание дерева в токенайзере.** Токенайзер
   получает `set_foreign_content(bool)` перед каждым `next()`; это и есть
   «adjusted current node» стандарта. Токенайзер остаётся без ссылки на дерево.

## Последствия

* Дерево: **1 556 → 1 792/1 792 (100 %)**, 0 пропусков и 0 исключений;
  фрагментных случаев 155 → 192.
* `Node` вырос на один `uint8_t`, `AttrRecord` — на один `uint32_t`. Дешевле,
  чем таблица «глобальное пространство имён на документ».
* Сериализаторы печатают пространство имён (`<svg font>`, `<math mi>`) и
  префикс атрибута (`xlink href`) в форме html5lib; `to_html` — в HTML-форме
  (`<svg><font></font></svg>`, `xlink:href="…"`).
* Всплыл посторонний пробел: «in caption» был схлопнут в in body, из-за чего
  `</table>` внутри `<caption><p>` не закрывал таблицу. Починен заодно:
  table-структурные токены теперь закрывают caption и переразбираются уровнем
  выше.
* Layout и paint пока рисуют SVG/MathML как обычные боксы: у разбора и
  отрисовки разные критерии готовности, и это отдельный этап.

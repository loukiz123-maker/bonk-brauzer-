# ADR 0014: table scope и судьба NUL

**Статус**: принято (этап 12).

## Контекст

Две независимые мелочи выглядели как «ещё немного правил», но обе оказались
вопросами модели.

1. **Scope.** У нас была одна функция `tag_in_scope()`, которая останавливается
   на `applet`, `caption`, `html`, `table`, `td`, `th`, `marquee`, `object`,
   `template`. Табличные режимы использовали её же — и получали неверный ответ:
   для `</table>` из ячейки она сообщала «таблицы в scope нет», потому что на
   пути стоит `td`. Стандарт же для табличных режимов использует отдельное
   понятие **table scope**, где границы только `html`, `table` и `template`.
2. **NUL.** Токенайзер в data state заменял U+0000 на U+FFFD. Это неверно:
   в data state NUL выдаётся как есть, а решение принимает режим вставки
   («in body» — игнорировать, текст в таблице — U+FFFD, `<select>` — игнорировать).

## Решение

1. Добавлена отдельная `in_table_scope(tag)`, и все табличные режимы
   (`table_end`, `table_body_end`, `row_*`, `cell_*`) переведены на неё. Правило
   стандарта «если в table scope нет нужного элемента — игнорировать токен»
   реализовано буквально: `if (!in_table_scope(...)) { report(...); return true; }`.
2. Токенайзер пропускает NUL в data state, дерево-строитель вызывает
   `sanitize_text(text, replacement)`.

## Почему это не «ещё один if»

Обе правки меняют *ответ на вопрос «можно ли»*, а не добавляют обработку случая:

* с table scope токены внутри таблицы начинают **игнорироваться** там, где
  раньше стек принудительно закрывался — это чинит не один документ, а всё
  семейство `<table><td>…</table>…`, `<table><td></td><tbody>`, вложенные
  таблицы в шаблонах;
* с NUL исчезает расхождение между слоями: токенайзер перестаёт «решать» за
  дерево, и нормальные символы (U+FFFD в тексте) больше не путаются с
  отброшенными NUL.

## Следствия

1. `tag_in_scope` и `in_table_scope` теперь две функции с разными границами, и
   путать их нельзя — в коде это подписано.
2. Собственный фикстур токенайзера пришлось привести к стандарту: он ожидал
   `\uFFFD` на выходе для `A\u0000`. Это ровно тот случай, когда «зелёный тест»
   охранял неверное поведение.
3. ASan поймал ошибку в первой версии `sanitize_text`: `std::string_view text =
   sanitize_text(...)` ссылался на временную строку. Исправлено хранением
   результата в локальной `std::string`.
4. Дальнейшие «in body» правила (заголовки, `<button>`, `</li>`, `<search>`)
   реализованы в том же стиле: явная проверка scope + генерация implied end tags,
   без специальных случаев в общем цикле.

# ADR 0003 — Арена на документ + генерационные хендлы

**Статус:** принято (этап 0), реализация `core/arena` готова

## Контекст

DOM-дерево, computed styles и layout-боксы живут одинаково долго — до следующей навигации или
полной пересборки документа. Внешний код (JS-биндинги, devtools, списки выделения) должен
ссылаться на узлы так, чтобы удаление узла не превращалось в use-after-free.

## Решение

1. **Арена** (`bonk::Arena`) владеет памятью узлов; освобождение — один `reset()`.
2. Публичные ссылки на узлы — **`NodeId { uint32 index; uint32 generation; }`** в
   `dom::Document`, разрешаемый через `resolve(NodeId) -> Result<Node*>`; удаление узла
   инкрементирует `generation` в слоте.
3. В арену кладутся только тривиально разрушаемые объекты; всё, что требует деструктора,
   живёт в обычных контейнерах.

## Почему не альтернативы

| Вариант | Проблема |
|---|---|
| `new`/`delete` на узел | миллионы `malloc/free`, фрагментация, медленное разрушение |
| `shared_ptr` повсюду | +24 байта на узел, циклы parent↔child через `weak_ptr`, рекурсивное разрушение |
| `unique_ptr` + сырые обратные указатели | разыменование «висячего» указателя не ловится, ошибки тихие |
| `Rc`/`RefCell`-стиль | не для C++ |

Генерация в хендле превращает use-after-free в проверяемую ошибку (`Result`) — это дешевле
(4 байта), чем любая схема с подсчётом ссылок.

## Последствия

- Арена аллоцирует блоками (`alignas(16)` заголовок, полезная нагрузка начинается
  выровненной — 64 KiB блок вмещает ровно 4096 объектов по 16 байт), `make<T>` не вызывает
  деструкторы — это записано в правилах заголовка.
- Тесты `arena.*` проверяют выравнивание, отсутствие пересечений, рост, `reset()`, move и
  плотность упаковки.
- Узлы не перемещаются в памяти при росте дерева (нет реаллокации) → указатели на `Node`
  стабильны, пока документ жив.

## Поправка (этап 2, после реализации DOM)

Практика показала, что арена — не лучший владелец *узлов*: `Node` получился POD-записью с
индексами, а не с указателями, и живёт в индексном пуле документа (`std::vector<Node>` +
свободные слоты). Причины:

1. `reset()` арены не нужен — сборка/уничтожение дерева это `vector::clear()`;
2. генерация для `NodeId` всё равно требует переиспользуемых слотов, а не только «вперёд»;
3. `std::vector` даёт подсчёт узлов, итерацию и отладку бесплатно.

Роль арены сужается до **покадровых буферов** (списки фрагментов отрисовки, временные
структуры layout/build, этап 5+). Само решение о генерационных хендлах остаётся в силе и
реализовано: `dom::NodeId{index, generation}` + `Document::is_alive()`, тесты `dom.node_ids_are_generational`.

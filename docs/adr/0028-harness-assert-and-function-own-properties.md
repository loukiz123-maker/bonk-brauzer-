# ADR 0028: `assert` как функция, собственные свойства функций, ошибки и `instanceof`

Дата: 2026-11-05. Этап: 26.

## Контекст

После этапа 25 отчёт показывал 649 падений `[object Object] is not a function` —
почти все в `built-ins/Array/prototype/*`. Разбор одного файла
(`Array/prototype/every/15.4.4.16-2-1.js`) с преамбулой раннера показал, что
дело не в движке: тест вызывает `assert(cond, msg)`, а преамбула объявляла
`var assert = {}`.

Дальше выяснилось, что `assert.throws(TypeError, fn)` не работает для ошибок,
которые бросает сам интерпретатор: они создаются `make_error(...)` и не имеют
прототипа конструктора, поэтому `e instanceof TypeError` — `false`. А
`verifyProperty(f, 'name', {configurable: true})` падал, потому что `name`
функции не был собственным свойством вообще (его отдавал `get_member`
синтетически).

## Решение

### 1. Преамбула: `assert` — функция с методами

`var assert = function (...) {...}` + прикреплённые `sameValue`, `throws` и т. д.
Это стало возможным только после этапа 23 (функции — объекты). Урок в ADR:
харнесс — тоже код, который надо проверять; «честный счёт» из ADR 0025 требует,
чтобы заглушки вели себя как настоящие файлы test262, а не как их удобное
подмножество.

### 2. `length`/`name`/`prototype` — настоящие собственные свойства

Они не хранятся в карте свойств (значение вычисляется из `Function`), но
`has_own_property`, `property_descriptor` и `own_property_keys` отвечают за них.
Флаги по ES2015 19.2.4: `length`/`name` — `writable: false, enumerable: false,
configurable: true`; `prototype` — `writable: true, enumerable: false,
configurable: false`.

Отвергнуто: материализовать их в `statics` при создании функции. Тогда
пришлось бы синхронизировать `length` при каждом изменении арности и следить,
чтобы `f.length = 5` не «сработало» (оно должно молча игнорироваться, потому что
`writable: false`), — а вычисление из полей `Function` даёт это бесплатно.

### 3. `instanceof` для внутренних ошибок — по имени

Ошибка интерпретатора — `Object::Kind::Error` с `name`/`message`, без прототипа
конструктора. Вариантов было два: (а) дать `make_error` доступ к рантайму и
проставлять прототипы, (б) отвечать в `instanceof` по имени. Выбрано (б):
`make_error` — свободная функция, которой пользуются десятки мест, и протаскивать
в неё `RuntimeState` ради проверки в одном операторе несоразмерно. Ограничение:
`Object.getPrototypeOf(err)` по-прежнему `Object.prototype`, а не
`TypeError.prototype`; это записано в открытые пункты.

### 4. `Array.from`/`Array.of` и проверка `length`

`Array.from` реализован через уже существующие `array_like_*` из ADR 0026 —
поэтому он одинаково работает с массивами, `arguments`, строками и обычными
объектами с `length`. Запись `length` у массива проверяется (ES2015 9.4.2.4):
`RangeError` на отрицательные, дробные и > 2³²−1 значения — и через присваивание,
и через `defineProperty`.

## Следствия

* test262: 5 130 → **6 850** (34.8 % → 46.4 %): +1 720 тестов, из которых
  подавляющее большинство — следствие одной строки в преамбуле.
* Юнит-тестов 472 → 476; strict-сборка без предупреждений.
* Ограничения: прототип у ошибок интерпретатора не выставлен, арность встроенных
  методов равна нулю (не заполнена), `Symbol.species` отсутствует.

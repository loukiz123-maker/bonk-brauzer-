# ADR 0004 — Растеризация: суперсэмплинг вместо hinting, PNG со stored-блоками

**Статус:** принято (этап 2)

## Решение

1. Глифы растеризуются **scanline-заливкой по правилу non-zero winding** с суперсэмплингом
   4×4 по пикселю; квадратичные кривые TrueType разворачиваются в полилинии адаптивным числом
   шагов (2..24) по длине сегмента.
2. Hinting не реализуется: он влияет на резкость мелкого текста, но не на корректность, и
   требует интерпретатора TrueType-инструкций (большой объём — этап 6, опция).
3. PNG пишется собственным энкодером: zlib-контейнер + deflate-блоки типа `stored`
   (без Huffman-кодирования) + свои CRC32/Adler32.

## Почему

- Декодер шрифта и растеризатор без зависимостей дают детерминированный результат: один и тот
  же шрифт + размер → один и тот же битмап на всех платформах, что делает скриншотные тесты
  возможными.
- Суперсэмплинг 4×4 = 16 сэмплов на пиксель: цена ~0.2 мс на глиф 20 px, зато нет «лестниц»
  на диагоналях и нет нужды в hinting для читаемости.
- `stored`-блоки — самый простой корректный deflate. Файлы большие (900×520 ≈ 1.8 МБ), но
  вывод валиден в любом просмотрщике; настоящий Huffman-энкодер — оптимизация этапа 6.

## Последствия

- Глифы кэшируются по (code point, размер) — повторные отрисовки бесплатны.
- Для репозитория скриншоты пере-упаковываются zlib'ом (см. `docs/screenshot.png`), потому что
  файлы движка слишком велики для git.
- Отсутствующие глифы рисуются синтетическим `.notdef`-боксом, чтобы «пустые» символы были
  заметны при отладке страниц (и в тестах на CJK).

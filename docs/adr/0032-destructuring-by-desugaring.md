# ADR 0032: деструктуризация десугариванием в парсере, присваивание — в интерпретаторе

Дата: 2026-11-05. Этап: 30.

## Контекст

Паттерны (`var [a, b] = x`, `function f({x})`, `for (var [k, v] of …)`) — это
синтаксис, у которого нет собственной семантики значений: он только раскладывает
уже существующие операции (чтение свойства, чтение элемента, присваивание,
`undefined`-проверка) в определённом порядке. Соблазн — завести `ExprKind::Pattern`
и отдельный интерпретатор паттернов; цена — второй обходчик AST, дублирующий
правила порядка вычислений.

## Решение

### 1. Объявления, параметры и циклы — десугаривание в парсере

`unpack_pattern(pattern, value, make_temp, bind)` превращает паттерн в набор
обычных привязок:

```js
var [a, b] = make();          // → var __bonk$v0 = make(), a = __bonk$v0[0], b = __bonk$v0[1];
function f({x}) {}            // → function f(__bonk$p0) { var __bonk$t0 = __bonk$p0,
                              //     x = __bonk$t0.x; … }
for (var [k, v] of pairs) {}  // → for (var __bonk$loop0 of pairs) { var k = …, v = …; … }
```

Три свойства, которые при этом приходится соблюдать:

1. **Источник вычисляется один раз.** На каждом уровне вложенности создаётся
   временная переменная, поэтому `var [a, b] = make()` вызывает `make` один раз,
   а `var {a: {b}} = o` читает `o.a` один раз (это видно по геттерам).
2. **Значения по умолчанию применяются только к `undefined`** и тоже через
   временную: `__t = value, name = (__t === undefined ? def : __t)`.
3. **Rest требует рантайма.** `[a, ...rest]` и `{a, ...others}` сводятся к двум
   служебным функциям движка, `__bonk$arrayRest(value, from)` и
   `__bonk$objectRest(value, excludedKeys)`; они устанавливаются в
   `install_builtins` рядом с остальными встроенными объектами.

Отвергнуто: отдельный узел `ExprKind::Pattern` и второй обходчик. Пришлось бы
повторить порядок вычислений, обработку геттеров и ошибок — то, что уже есть в
`eval`/`set_member`.

Отвергнуто: разворачивать `var [a, b] = x` в несколько *операторов*. В этом
движке блок создаёт область видимости, поэтому `var` внутри блока перестал бы
быть функциональным; один декларатор с несколькими именами сохраняет и область,
и порядок.

### 2. Деструктурирующее присваивание — в интерпретаторе

`[a, b] = value` и `({x: o.x} = value)` **не** десугарируются. Причина —
неоднозначность: внутри паттерна `{} = 42` означает «значение по умолчанию для
под-паттерна» (`function f({x: {} = 42})`), а в позиции выражения — присваивание.
Парсер не знает контекста, поэтому решение принимает интерпретатор:
`assign_pattern` в ветке `Assign` (только при `=` и цели-литерале).

`assign_pattern` поддерживает идентификаторы, члены, вложенные паттерны,
значения по умолчанию и rest; значением выражения остаётся правый операнд.
Первая версия (десугаривание через `Sequence` выражений) была именно такой и
отброшена после того, как 280 файлов test262 перестали разбираться.

### 3. Spread — отдельный узел, потому что это значение

`...expr` в литерале массива, в аргументах и в объектном литерале — это
`ExprKind::Spread` (`PropertyDef::Kind::Spread` для объектов). Раскрытие живёт в
`spread_values` (массивы, строки, array-like; примитив — `TypeError`) и
`copy_own_enumerable` (собственные перечисляемые свойства, `null`/`undefined`
ничего не добавляют). Узел добрался до `eval` вне контейнера — это `SyntaxError`,
а не «тихо проигнорировать».

## Следствия

* test262: пройдено 7 453 → **8 835** (+1 382) при конверте 15 044 → 17 538
  (раскрыты `destructuring-binding`, `spread`, `rest-parameters`,
  `default-parameters`, `object-spread`, `object-rest`), 50.4 %.
* Юнит-тестов 504 → 514 (`tests/js/destructuring_test.cpp`).
* Найдено и исправлено два бага, не связанных с паттернами: дыры в литералах
  массива давали `nullptr` в AST и SIGSEGV (175 файлов), а `[...5]` не парсился
  из-за лексера, видевшего в третьей точке начало числа `.5`.
* Ограничение: служебные имена (`__bonk$…`) видны в глобальной области как
  обычные переменные; вычисляемые ключи в паттернах (`{[k]: v} = o`) не
  поддерживаются, как и паттерны в `catch`.

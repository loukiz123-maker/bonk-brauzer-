# ADR 0021: регистр имён в DOM API и селекторах зависит от пространства имён

**Статус**: принято (этап 19).

## Контекст

Этап 18 научил парсер пространствам имён, но дальше парсера они не пошли.
Последствия были видны сразу:

* `getElementsByTagName("DIV")` возвращал пустой список — сравнение было
  побайтовым, хотя в HTML-документе имя HTML-элемента сравнивается без учёта
  регистра;
* `getElementsByTagName("foreignobject")` и `querySelector("foreignObject")`
  расходились: первое не находило `<foreignObject>`, второе не находило вообще
  ничего, потому что разбор селектора приводил имя к нижнему регистру и оно
  переставало совпадать с настоящим именем элемента;
* правило CSS `foreignObject { … }` поэтому не применялось никогда.

Одновременно в токенайзере оставался блок «известных расхождений»: 54 случая
пропускались по подстроке описания. Половина из них проходила и была скрыта
слишком широким шаблоном, а четыре записи («спек даёт U+FFFD вместо NUL»)
противоречили стандарту: в data state символ U+0000 выдаётся как есть.

## Решение

1. **Регистр — функция пространства имён.** И `getElementsByTagName`, и
   тип-селекторы сравнивают имя так:

   | элемент | сравнение |
   |---|---|
   | HTML | ASCII case-insensitive (`DIV` → `<div>`) |
   | SVG / MathML | точное (`foreignObject`, `linearGradient`, `feBlend`) |

   Это дословно DOM-стандарт для `getElementsByTagName` в HTML-документе и CSS
   Selectors для тип-селекторов. `*` возвращает всё, независимо от пространства.

2. **Разбор селектора сохраняет написание.** `SimpleSelector::tag` больше не
   приводится к нижнему регистру: решение о регистре откладывается до момента
   сопоставления, когда известен элемент. Каскад CSS получает это бесплатно —
   он ходит через тот же `dom::matches_any`.

3. **Пропуск в токенайзере — по форме ожидания, а не по списку.** Таблица
   `kKnownDivergences` удалена. Остались два структурных условия, оба про
   html5lib-модель processing instruction: ввод начинается с `<?`, а ожидание
   пустое (25 случаев), либо в ожидаемом выводе есть токен `ProcessingInstruction`
   (3 случая). Если корпус перейдёт на комментарии, случаи пойдут в прогон сами:
   проверка «ожидание пустое» перестанет срабатывать.

4. **CDATA-секция доступна как начальное состояние.** `Tokenizer::enter_cdata_section()`
   выставляет то же состояние, в которое tree builder попадает из `markup
   declaration open` внутри внешнего контента. Это единственное состояние из
   шести, которое корпус умел запрашивать, а движок — нет.

## Последствия

* Токенайзер: 6 768 → **6 792/6 820 (99.6 %)**, 0 падений, пропусков 52 → 28;
  счётчик «неизвестное начальное состояние» исчез.
* Юнит-тестов 403 → 409; каждый закрытый кластер пропусков закреплён тестом
  (`tokenizer.cdata_section_state`, `tokenizer.unexpected_question_mark_is_a_bogus_comment`,
  `dom.type_selectors_follow_the_namespace`, `dom.foreign_elements_are_visible_to_tag_name_lookups`,
  `css.foreign_type_selectors_keep_their_case`).
* Отчёт стал честнее: причины пропусков считаются по существу (состояние,
  namespace-имена, PI-модель, несмоделированный вывод), а не по подстрокам.
* `SimpleSelector::text()` теперь печатает селектор в том написании, в котором
  его дали (`DIV` останется `DIV`). Для канонизации в логах это неудобно, зато
  честно по отношению к автору селектора.
* Следующий крупный блок — не разбор, а отрисовка: SVG/MathML пока
  раскладываются как обычные боксы.
